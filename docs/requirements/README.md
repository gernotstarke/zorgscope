# zorgscope – Requirements

Structured loosely after [req42](https://req42.de). Every requirement has a stable id that is referenced
from architecture, plans, tests and commit messages.

| # | Chapter | Ids |
|---|---------|-----|
| 1 | [Goals and vision](01-goals.md) | G‑x, QG‑x |
| 2 | [Stakeholders](02-stakeholders.md) | S‑x |

| 4 | [Functional requirements](04-functional-requirements.md) | E‑x (epics), FR‑x (stories) |
| 5 | [Quality requirements](05-quality-requirements.md) | QS‑x (scenarios) |
| 6 | [Constraints](06-constraints.md) | C‑x |
| 7 | [Glossary](07-glossary.md) | — |
| 8 | [Assumptions, risks, open points](08-assumptions-risks-open-points.md) | A‑x, R‑x, O‑x |

Priorities use MoSCoW: **M**ust (v1), **S**hould (v1 if cheap), **C**ould (later), **W**on't (explicitly out of scope for now).

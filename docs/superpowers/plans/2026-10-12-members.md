# Members Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Invited iSAQB people sign in with GitHub, choose up to 12 public repositories of one
organisation, and see their own list, tiles, radar, contributors and search — on the same
deployment, without touching Gernot's view.

**Architecture:** Admission gains a second rule (write access on `gernotstarke/zorgscope-members`)
answered by the same adapter that answers the first. The session cookie moves from signed to
encrypted (AES‑GCM) and carries role, login and — for a member — their unscoped OAuth token and
their selection. Every signed-in handler renders from a *scope* resolved from the session: the
configuration and the one cache for an owner; the selection, one generated site per repository and
a per-member `snapshot.Cache` (fetched with the member's token) for a member. A new `/repos` page
edits the selection. Sign-out revokes a member's token at GitHub.

**Tech Stack:** Go 1.26, `html/template`, `crypto/aes` + `crypto/cipher` (GCM), `shurcooL/githubv4`,
Docker-only toolchain (`make check`).

**Spec:** `docs/superpowers/specs/2026-10-12-members-design.md`

## Global Constraints

- Version **2.5.0** (`internal/version/version.go`), README changelog row dated 2026-10-12.
- No inline `style` attribute, no inline script (QS‑4.4); every colour is a `hue-<key>` class.
- `MaxMemberRepos = 12`; a member fetch costs at most 12 × 2 = 24 requests on the member's own
  token (QS‑3.5); the owner's budget (≤ 19 repositories, ≤ 38 requests) is unchanged.
- A member's fetcher carries the member's token only: `github.Config.OwnerTokens` is nil for it
  (ADR‑0017's per-owner tokens read private repositories and are the owner's alone).
- Member session TTL **7 days**; owner **30 days** (unchanged). Session key context
  `"zorgscope-session-v3"`; every v2 cookie is refused.
- A member's token never reaches a log line, a response body or an error text (QS‑4.3). The only
  place it lives is the encrypted cookie and the per-request fetch.
- `members_repo` and `members_org` come as a pair; one without the other fails `config.Load`.
- Owner wins: push/admin on `auth_repo` is checked first; the members repository is asked only
  when that refused and members are configured.
- Member sites: `Name` = the part after `/`, `URL` = `https://github.com/<repo>`, `Repos` = that
  one repository, `Hue` = `config.MemberHues[i]` in selection order, `NoAlerts` = true, no Tag,
  `Group` = `member` (a family none of the fixed radars names, so no radar is offered and every
  site is a sector — ADR‑0018).
- `config.Site.Repos` is a slice since 2.3.0: build sites with `Repos: []string{repo}`, never `Repo:`.
  `config.Site` is therefore not comparable with `==`; compare fields or use `reflect.DeepEqual`.
- Go runs only in Docker. Single package test:
  `docker run --rm -t -v "$PWD":/src -w /src -v zorgscope-gomod:/go/pkg/mod -v zorgscope-gocache:/root/.cache/go-build golang:1.26 go test ./internal/<pkg>/... -run <Name> -v`
  (abbreviated below as `GOTEST ./internal/<pkg>/... -run <Name>`). Full gate: `make check`.
- Commit messages follow the repo style (`feat(web): … (FR-8.4)`) and end with
  `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. **A member whose cookie says 13 repositories, or a repository not in `owner/name` form** (a
   hand-crafted or future-format cookie): must be a sign-in, never a 500 or an over-budget fetch.
   Pinned in Task 4 (`decode` refuses) and Task 7 (`POST /repos` refuses 13).
2. **A member who is also a collaborator of zorgscope** (Gernot adding himself by mistake): must
   get the owner view, and the members repository must never be asked. Pinned in Task 5.
3. **The organisation list fails while a member has a selection**: `GET /repos` must still show
   their current repositories checked and `POST /repos` must save nothing. Pinned in Task 7.
4. **A fetch error quoting the member's token** (GitHub's "Bad credentials for gho_…"): must reach
   the page's error notice and the log scrubbed. Pinned in Task 6 (`memberSource`) and Task 8
   (the canary sweep).
5. **A member with an empty selection pressing Refresh or polling `/items`**: must land on `/repos`
   without a 500 and without a fetch of zero repositories. Pinned in Task 6.

```go
package github

import (
	"bytes"
	"context"
	"encoding/json"
	"errors"
	"fmt"
	"io"
	"net/http"
	"regexp"
	"strings"

	"github.com/gernotstarke/zorgscope/internal/ports"
)

// Access answers the sign-in questions with the visitor's own token — may this person push to a
// repository, who are they, which public repositories may they choose — and revokes a token when
// they sign out. It is a ports.AccessChecker, ports.IdentityReader, ports.RepoLister and
// ports.TokenRevoker (FR-8.3, FR-8.4, FR-8.5).
type Access struct {
	apiBase                string // "" means https://api.github.com
	clientID, clientSecret string // the OAuth App, for revocation
	hc                     *http.Client
}

// NewAccess builds the adapter. apiBase is the REST root, which is what GITHUB_BASE_URL points at
// the fixture server; empty means the real GitHub.
func NewAccess(apiBase, clientID, clientSecret string, hc *http.Client) *Access {
	if apiBase == "" {
		apiBase = "https://api.github.com"
	}
	return &Access{apiBase: strings.TrimRight(apiBase, "/"), clientID: clientID, clientSecret: clientSecret, hc: hc}
}

// accessBodyLimit bounds what is read from GitHub's answer. A repository object or a page of a
// hundred of them is tens of kilobytes; a megabyte is far more than it can be and far less than a
// hostile endpoint could otherwise make this process allocate on an unauthenticated route.
const accessBodyLimit = 1 << 20

// do sends a request with token and answers the response, or an error that names the status and
// never the token (QS-4.3). The transport error is deliberately dropped rather than wrapped: it
// quotes the request, and the request carries the Authorization header in some transports' wording.
func (a *Access) do(ctx context.Context, method, url, token string, body io.Reader, what string) (*http.Response, error) {
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		return nil, fmt.Errorf("%s: building the request: %w", what, err)
	}
	if token != "" {
		req.Header.Set("Authorization", "Bearer "+token)
	}
	req.Header.Set("Accept", "application/vnd.github+json")
	req.Header.Set("X-GitHub-Api-Version", "2022-11-28")
	resp, err := a.hc.Do(req)
	if err != nil {
		return nil, fmt.Errorf("%s: the request to GitHub failed", what)
	}
	return resp, nil
}

// HasPushAccess makes one request with the visitor's token and reads the permissions block GitHub
// returns for the authenticated user on repo. Push or admin admits; a missing block, any other
// status and any transport error refuse — the check fails closed.
func (a *Access) HasPushAccess(ctx context.Context, token, repo string) (bool, error) {
	resp, err := a.do(ctx, http.MethodGet, a.apiBase+"/repos/"+repo, token, nil, "access check")
	if err != nil {
		return false, err
	}
	defer func() { _ = resp.Body.Close() }()
	if resp.StatusCode != http.StatusOK {
		// The status and nothing else: echoing an upstream body into an error is how a credential
		// eventually reaches a log.
		return false, fmt.Errorf("access check: GitHub answered %d", resp.StatusCode)
	}
	var body struct {
		Permissions *struct{ Admin, Push bool } `json:"permissions"`
	}
	if err := json.NewDecoder(io.LimitReader(resp.Body, accessBodyLimit)).Decode(&body); err != nil {
		return false, fmt.Errorf("access check: reading the answer: %w", err)
	}
	if body.Permissions == nil {
		return false, ports.ErrNoPermissionsBlock
	}
	return body.Permissions.Push || body.Permissions.Admin, nil
}

// Login asks GET /user who the token belongs to.
func (a *Access) Login(ctx context.Context, token string) (string, error) {
	resp, err := a.do(ctx, http.MethodGet, a.apiBase+"/user", token, nil, "identity")
	if err != nil {
		return "", err
	}
	defer func() { _ = resp.Body.Close() }()
	if resp.StatusCode != http.StatusOK {
		return "", fmt.Errorf("identity: GitHub answered %d", resp.StatusCode)
	}
	var body struct {

		return fmt.Errorf("revocation: building the request: %w", err)
	}

	req.Header.Set("Content-Type", "application/json")

		return fmt.Errorf("revocation: GitHub answered %d", resp.StatusCode)
```

```go
	Token string
	Repos []string

// member reports whether this is a member's session.
func (s session) member() bool { return s.Role == roleMember }

// sessionWire is the cookie's plaintext.
type sessionWire struct {
	Exp   int64    `json:"exp"`
	Role  string   `json:"role"`
	Login string   `json:"login"`
	Token string   `json:"tok,omitempty"`
	Repos []string `json:"repos,omitempty"`
}

// sessionCodec mints and opens session cookie values.
//
// A cookie value is base64url(nonce ‖ AES-256-GCM(key, nonce, json)), where the key is SHA-256 of
// sessionKeyContext concatenated with GITHUB_OAUTH_CLIENT_SECRET. GCM authenticates as well as
// encrypts, so a forged or altered value fails to open, and rotating the client secret changes the
// key and ends every session at once — FR-8.3 AC4 without a session table. Encryption rather than
// a signature because a member's cookie carries their token, which must be confidential to the
// browser and to anyone who copies the cookie, not merely tamper-proof.
type sessionCodec struct{ aead cipher.AEAD }

func newSessionCodec(secret string) *sessionCodec {
	key := sha256.Sum256([]byte(sessionKeyContext + secret))
	block, err := aes.NewCipher(key[:])
	if err != nil {
		panic(err) // a 32-byte key never fails
	}
	aead, err := cipher.NewGCM(block)
	if err != nil {
		panic(err)
	}
	return &sessionCodec{aead: aead}
}

// mint returns the cookie value for s.
func (c *sessionCodec) mint(s session) string {
	plain, err := json.Marshal(sessionWire{
		Exp: s.Expiry.Unix(), Role: string(s.Role), Login: s.Login, Token: s.Token, Repos: s.Repos,
	})
	if err != nil {
		panic(err) // strings and ints only
	}
	nonce := make([]byte, c.aead.NonceSize())
	if _, err := rand.Read(nonce); err != nil {
		panic(err) // crypto/rand never fails on a platform this runs on; Go crashes before returning one
	}
	return sessionEncoding.EncodeToString(c.aead.Seal(nonce, nonce, plain, nil))
}

// decode returns the session a cookie value proves, and false when the value did not come from
// this codec, has expired, or names something a session may not: an unknown role, a login that is
// not one, a member without a token, more than config.MaxMemberRepos repositories or one not in
// owner/name form. Every refusal is a sign-in, never a 500 (spec 2026-10-12 §4).
func (c *sessionCodec) decode(value string, now time.Time) (session, bool) {
	raw, err := sessionEncoding.DecodeString(value)
	if err != nil || len(raw) < c.aead.NonceSize() {
		return session{}, false
	}
	nonce, sealed := raw[:c.aead.NonceSize()], raw[c.aead.NonceSize():]
	plain, err := c.aead.Open(nil, nonce, sealed, nil)
	if err != nil {
		return session{}, false
	}
	var w sessionWire
	if err := json.Unmarshal(plain, &w); err != nil {
		return session{}, false
	}
	s := session{Expiry: time.Unix(w.Exp, 0), Role: role(w.Role), Login: w.Login, Token: w.Token, Repos: w.Repos}
	switch {
	case s.Role != roleOwner && s.Role != roleMember:
		return session{}, false
	case !config.IsLogin(s.Login):
		return session{}, false
	case s.member() && s.Token == "":
		return session{}, false
	case len(s.Repos) > config.MaxMemberRepos:
		return session{}, false
	}
	for _, repo := range s.Repos {
		if !config.IsRepo(repo) {
			return session{}, false
		}
	}
	return s, now.Before(s.Expiry)
}
```

```go
package web

import (
	"context"
	"crypto/sha256"
	"encoding/hex"
	"errors"
	"log/slog"
	"strings"
	"sync"
	"time"

	"github.com/gernotstarke/zorgscope/internal/domain"
	"github.com/gernotstarke/zorgscope/internal/ports"
	"github.com/gernotstarke/zorgscope/internal/snapshot"
)

// maxMemberCaches bounds how many members' caches are held at once. The allowlist is a handful of
// people; this is a backstop against the map growing without limit, like the sign-in limiter's
// maxTrackedClients. Beyond it the least recently used entry is dropped — that member's next page
// view pays one fetch, the same thing a Machine waking from zero costs everyone.
const maxMemberCaches = 64

// memberCaches holds one snapshot.Cache per signed-in member (spec 2026-10-12 §8), keyed by
// login. The cache package is not changed: each member gets the owner's semantics — fetch on a
// stale page view, the wait page, partial failures kept — over their own repositories, fetched
// with their own token.
type memberCaches struct {
	mu        sync.Mutex
	entries   map[string]*memberEntry
	newSource func(token string, repos []string) ports.Source
	ttl       time.Duration
	clock     ports.Clock
	log       *slog.Logger
}

// memberEntry is one member's cache and the fingerprint of the token and selection it was built
// for. A session whose fingerprint differs — a new token after signing in again, a new selection —
// replaces the entry rather than invalidating it: the old cache holds items of a different
// selection, and nothing of it is worth keeping.
type memberEntry struct {
	fingerprint string
	cache       *snapshot.Cache
	lastUsed    time.Time
}

func newMemberCaches(newSource func(token string, repos []string) ports.Source, ttl time.Duration, clock ports.Clock, log *slog.Logger) *memberCaches {
	return &memberCaches{entries: make(map[string]*memberEntry), newSource: newSource, ttl: ttl, clock: clock, log: log}
}

// cacheFor returns the cache for sess, building it when the member has none yet or theirs was
// built for another token or selection.
func (m *memberCaches) cacheFor(sess session) *snapshot.Cache {
	fp := memberFingerprint(sess.Token, sess.Repos)
	m.mu.Lock()
	defer m.mu.Unlock()
	now := m.clock.Now()
	if e, ok := m.entries[sess.Login]; ok && e.fingerprint == fp {
		e.lastUsed = now
		return e.cache
	}
	m.evictLocked()
	src := memberSource(m.newSource(sess.Token, sess.Repos), sess.Token, sess.Login, len(sess.Repos), m.log)
	e := &memberEntry{fingerprint: fp, cache: snapshot.New(src, m.ttl, m.clock), lastUsed: now}
	m.entries[sess.Login] = e
	return e.cache
}

// evictLocked drops the least recently used entries until there is room for one more. The caller
// holds the mutex. An entry being replaced counts as room: it is overwritten by its own login.
func (m *memberCaches) evictLocked() {
	for len(m.entries) >= maxMemberCaches {
		oldestKey, oldest := "", time.Time{}
		for key, e := range m.entries {
			if oldest.IsZero() || e.lastUsed.Before(oldest) {
				oldestKey, oldest = key, e.lastUsed
			}
		}
		delete(m.entries, oldestKey)
	}
}

// memberFingerprint identifies a (token, selection) pair without keeping either in the clear.
func memberFingerprint(token string, repos []string) string {
	h := sha256.New()
	_, _ = h.Write([]byte(token))
	for _, repo := range repos {
		_, _ = h.Write([]byte{0})
		_, _ = h.Write([]byte(repo))
	}
	return hex.EncodeToString(h.Sum(nil))
}

// memberSource wraps a member's source for the two things every consumer of its result needs
// (spec §8, §10): a log line per fetch with the login, and no token in any error. The error text
// reaches both the log and the page's error notice, so it is scrubbed here, once, before either
// can see it (QS-4.3). The scrubbed error is a new value: nothing downstream matches on the
// original's type.
func memberSource(src ports.Source, token, login string, repos int, log *slog.Logger) ports.Source {
	return ports.SourceFunc(func(ctx context.Context) (domain.Fetched, error) {
		log.Info("member fetch", "login", login, "repos", repos)
		got, err := src.Fetch(ctx)
		if err != nil {
			err = scrubbedError(err, token)
			log.Warn("member fetch failed", "login", login, "repos", repos, "items", len(got.Items), "err", err.Error())
		}
		return got, err
	})
}

// scrubbedError is err's text with token replaced by "[token]", as a new error value. It is the
// one way a member's token leaves any error in this package (QS-4.3): fetch errors here, the
// repository list's and the revocation's in repos.go and dashboard.go.
func scrubbedError(err error, token string) error {
	text := err.Error()
	if token != "" {
		text = strings.ReplaceAll(text, token, "[token]")
	}
	return errors.New(text)
}
```

```go
package web

import (
	"context"
	"net/http"
	"strings"

	"github.com/gernotstarke/zorgscope/internal/config"
	"github.com/gernotstarke/zorgscope/internal/snapshot"
)

// scope is what a signed-in page renders from (spec 2026-10-12 §5): the repositories, the sites
// drawn as tiles and sectors, the login "needs you" means, and the cache the items come from. The
// owner's scope is the configuration and the one cache main builds; a member's is their selection,
// one generated site per repository, themselves as owner, and a cache of their own. Every handler
// reads these four from the scope and never from the configuration directly, which is what keeps
// the owner's pages and a member's pages one set of code.
type scope struct {
	GH     config.GitHub
	Cache  *snapshot.Cache
	Member bool
	Login  string
}

// sessionKey carries the decoded session from requireSession to the handler behind it.
type sessionKey struct{}

// sessionOf is the session requireSession admitted the request on. On a public route it is the
// zero session, which is nobody's.
func sessionOf(r *http.Request) session {
	s, _ := r.Context().Value(sessionKey{}).(session)
	return s
}

func withSession(r *http.Request, sess session) *http.Request {
	return r.WithContext(context.WithValue(r.Context(), sessionKey{}, sess))
}

// scopeFor is the scope sess sees.
func (s *Server) scopeFor(sess session) scope {
	if !sess.member() {
		return scope{GH: s.cfg.GitHub, Cache: s.cache, Login: sess.Login}
	}
	return scope{GH: memberGitHub(s.cfg.GitHub, sess), Cache: s.members.cacheFor(sess), Member: true, Login: sess.Login}
}

// scopeOf resolves the request's scope. A member who has chosen nothing yet has no scope to
// render: the request is answered here — a page is sent to /repos, an htmx fragment gets 204 with
// HX-Redirect — and false says so. Nothing is fetched for a selection of nothing.
func (s *Server) scopeOf(w http.ResponseWriter, r *http.Request) (scope, bool) {
	sess := sessionOf(r)
	if sess.member() && len(sess.Repos) == 0 {
		if r.Header.Get("HX-Request") == "true" {
			w.Header().Set("HX-Redirect", "/repos")
			w.WriteHeader(http.StatusNoContent)
			return scope{}, false
		}
		http.Redirect(w, r, "/repos", http.StatusSeeOther)
		return scope{}, false
	}
	return s.scopeFor(sess), true
}

// memberGroup is the family a member's sites belong to. None of the fixed radars (ADR-0018) names
// it, so no radar is offered for a member: every site is a sector and no switch is drawn.
const memberGroup = "member"

// memberGitHub is a member's configuration: the deployment's settings with the repositories,
// owner and sites replaced by the member's. One site per repository, named after it, in the plain
// hue of its position (config.MemberHues has exactly MaxMemberRepos entries, D11), alerts off, in
// the member family — so the radar has no switch and the tiles no Other.
func memberGitHub(base config.GitHub, sess session) config.GitHub {
	gh := base
	gh.Repos, gh.Owner = sess.Repos, sess.Login
	gh.Sites = make([]config.Site, 0, len(sess.Repos))
	for i, repo := range sess.Repos {
		gh.Sites = append(gh.Sites, config.Site{
			Name:     repo[strings.IndexByte(repo, '/')+1:],
			URL:      "https://github.com/" + repo,
			Repos:    []string{repo},
			Hue:      config.MemberHues[i%len(config.MemberHues)],
			Group:    memberGroup,
			NoAlerts: true,
		})
	}
	return gh
}
```

```go
import (
	"context"
	"net/http"
	"strconv"
	"strings"
	"sync"
	"time"

	"github.com/gernotstarke/zorgscope/internal/config"
	"github.com/gernotstarke/zorgscope/internal/ports"

// orgReposTTL is how long the organisation's repository list is reused before a member's page view
// refetches it. It is public data that changes a few times a year; an hour keeps the page off
// GitHub's rate limit for the people who open it ten times while deciding.
const orgReposTTL = time.Hour

// orgRepos is the one list, shared by every member: public data fetched with whichever member's
// token asked first after it went stale (spec 2026-10-12 §7).
type orgRepos struct {
	mu        sync.Mutex
	list      []ports.Repo
	fetchedAt time.Time
}

// orgRepoList returns the organisation's repositories, fetching them with token when the held
// list is older than orgReposTTL. A failed fetch returns the error and keeps whatever was held:
// a stale list is better than none for a page that only ticks boxes.
func (s *Server) orgRepoList(ctx context.Context, token string) ([]ports.Repo, error) {
	s.orgRepos.mu.Lock()
	defer s.orgRepos.mu.Unlock()
	now := s.clock.Now()
	if s.orgRepos.list != nil && now.Sub(s.orgRepos.fetchedAt) <= orgReposTTL {
		return s.orgRepos.list, nil
	}
	list, err := s.repos.PublicRepos(ctx, token, s.cfg.GitHub.MembersOrg)
	if err != nil {
		return s.orgRepos.list, scrubbedError(err, token)
	}
	s.orgRepos.list, s.orgRepos.fetchedAt = list, now
	return list, nil
}

// reposView is the repository page (FR-8.5).
type reposView struct {
	Login, Org  string
	Max, Chosen int
	Rows        []repoRow
	// Error is why the page could not do what was asked: the list could not be fetched, or
	// too many were chosen. The list is still drawn from whatever is known.
	Error string
	Saved bool
}

// repoRow is one checkbox.
type repoRow struct {
	FullName, Name, Description string
	Checked                     bool
}

// reposPage builds the view for sess over list, marking chosen; listErr, when set, is shown.
func reposPage(sess session, org string, list []ports.Repo, chosen []string, listErr error) reposView {
	picked := make(map[string]bool, len(chosen))
	for _, repo := range chosen {
		picked[repo] = true
	}
	v := reposView{Login: sess.Login, Org: org, Max: config.MaxMemberRepos, Chosen: len(chosen)}
	known := make(map[string]bool, len(list))
	for _, repo := range list {
		known[repo.FullName] = true
		v.Rows = append(v.Rows, repoRow{
			FullName: repo.FullName, Name: repo.FullName[strings.IndexByte(repo.FullName, '/')+1:],
			Description: repo.Description, Checked: picked[repo.FullName],
		})
	}
	// A chosen repository the list does not hold — the list failed, or the repository went
	// private or archived since — is still drawn, checked, so the member can unchoose it.
	for _, repo := range chosen {
		if !known[repo] {
			v.Rows = append(v.Rows, repoRow{FullName: repo, Name: repo[strings.IndexByte(repo, '/')+1:], Checked: true})
		}
	}
	if listErr != nil {
		v.Error = "The organisation's repositories could not be fetched: " + listErr.Error()
	}
	return v
}

// handleRepos shows the page (FR-8.5). The owner has no selection and is sent to the dashboard.
func (s *Server) handleRepos(w http.ResponseWriter, r *http.Request) {
	sess := sessionOf(r)
	if !sess.member() {
		http.Redirect(w, r, "/", http.StatusSeeOther)
		return
	}
	list, err := s.orgRepoList(r.Context(), sess.Token)
	view := reposPage(sess, s.cfg.GitHub.MembersOrg, list, sess.Repos, err)
	view.Saved = r.URL.Query().Get("saved") == "1"
	s.execute(w, r, http.StatusOK, "repos.html", pageData{Title: "Repositories", Repos: &view})
}

// handleReposSave records the selection in the cookie (FR-8.5). Only repositories the
// organisation list holds are kept, each once, in the list's order; more than
// config.MaxMemberRepos is refused with the page redrawn and nothing saved; a list that cannot be
// fetched refuses the same way, because nothing can be validated against it.
func (s *Server) handleReposSave(w http.ResponseWriter, r *http.Request) {
	sess := sessionOf(r)
	if !sess.member() {
		http.Redirect(w, r, "/", http.StatusSeeOther)
		return
	}
	if err := r.ParseForm(); err != nil {
		s.fail(w, r, "reading the form", err)
		return
	}
	asked := make(map[string]bool, len(r.PostForm["repo"]))
	for _, repo := range r.PostForm["repo"] {
		asked[repo] = true
	}
	list, err := s.orgRepoList(r.Context(), sess.Token)
	if err != nil {
		view := reposPage(sess, s.cfg.GitHub.MembersOrg, list, sess.Repos, err)
		s.execute(w, r, http.StatusOK, "repos.html", pageData{Title: "Repositories", Repos: &view})
		return
	}
	var chosen []string
	for _, repo := range list {
		if asked[repo.FullName] {
			chosen = append(chosen, repo.FullName)
		}
	}
	if len(chosen) > config.MaxMemberRepos {
		view := reposPage(sess, s.cfg.GitHub.MembersOrg, list, chosen, nil)
		view.Error = "Choose at most " + strconv.Itoa(config.MaxMemberRepos) + " repositories — " +
			strconv.Itoa(len(chosen)) + " are ticked."
		s.execute(w, r, http.StatusOK, "repos.html", pageData{Title: "Repositories", Repos: &view})
		return
	}
	sess.Repos = chosen
	s.setSession(w, sess)
	if len(chosen) == 0 {
		http.Redirect(w, r, "/repos?saved=1", http.StatusSeeOther)
		return
	}
	http.Redirect(w, r, settingsOf(r).Landing.path(), http.StatusSeeOther)
}
```

```go
// handleLogout ends the session: for a member, first their token at GitHub (spec 2026-10-12 §9),
// so that a copy of the cookie dies with it; then the cookie, for everyone. The cookie is cleared
// whatever GitHub said — the visitor asked to be signed out of this browser, and that never
// depends on an upstream. It is the one sign-out a visitor can reach for themselves; the other is
// rotating the OAuth client secret (FR-8.3 AC4).
func (s *Server) handleLogout(w http.ResponseWriter, r *http.Request) {
	sess := sessionOf(r)
	revoked := false
	if sess.member() {
		if err := s.revoker.Revoke(r.Context(), sess.Token); err != nil {
			s.log.Warn("sign-out revocation failed", "login", sess.Login, "err", scrubbedError(err, sess.Token).Error())
		} else {
			revoked = true
		}
	}
	s.log.Info("sign-out", "login", sess.Login, "role", sess.Role, "revoked", revoked)
	http.SetCookie(w, &http.Cookie{
		Name: sessionCookieName, Value: "", Path: "/", MaxAge: -1,
		HttpOnly: true, Secure: true, SameSite: http.SameSiteLaxMode,
	})
	http.Redirect(w, r, "/login", http.StatusSeeOther)
}
```

```markdown
# 0019. Members: an allowlist by a second repository, a personal scope in an encrypted cookie, fetches on the member's own token

* Status: accepted (implemented in 2.5.0)
* Date: 2026-10-12
* Requirements: FR‑1.17, FR‑8.3, FR‑8.4, FR‑8.5, QS‑3.5, QS‑4.3
* Builds on: [ADR‑0009](0009-github-sign-in-push-access.md), [ADR‑0010](0010-stateless-no-database.md), [ADR‑0017](0017-a-token-per-repository-owner.md), [ADR‑0018](0018-fixed-radars-over-families.md)

## Context and problem statement

People from the iSAQB saw zorgscope's radar and asked for the same over their own repositories. The
product was built for one person (ADR‑0009, ADR‑0010, PRODUCT.md): admission is push access on one
repository, the session cookie carries nothing but an expiry, the one snapshot is the configured
nineteen repositories fetched with the owner's tokens. The question: how does a handful of invited
people get a personal list, tiles and radar on this deployment, without a database, without
touching the owner's view, and without their usage degrading it?

## Considered options

* Where it runs: **one deployment** admitting a second audience; or a second Fly app and OAuth App.
* Who is admitted: **write access on a second public repository**, managed on GitHub's
  collaborator page; or organisation membership (needs `read:org`); or an allowlist in the
  configuration file; or a CRUD page over a database.
* Whose token fetches: **the member's own unscoped OAuth token**, kept in the cookie; or the
  owner's `GITHUB_TOKEN` for everyone; or a pasted personal access token per member.
* Where the selection lives: **the cookie**; or a Fly Volume with SQLite.

## Decision outcome

Chosen: the bold options above (spec `docs/superpowers/specs/2026-10-12-members-design.md`,
D1–D12). The admission rule reuses ADR‑0009's mechanism against a second repository, so managing
members is GitHub's collaborator page and nothing to deploy. The session cookie moves from signed
to encrypted (AES‑GCM under a key derived from the client secret, as before) and carries role,
login and — for a member — their token and selection, so the server still remembers nothing
(ADR‑0010). Every page renders from a scope resolved from the session; a member's scope is a
`snapshot.Cache` of their own, fetched with their own token over at most twelve repositories, so
their usage spends their rate limit and never the owner's.

### Consequences

* Good: nothing new to operate — one app, one OAuth App, no scope, no secret, no database.
* Good: the owner's pages run the same code on the same values as before; members cannot make
  them stale or failing.
* Good: adding or removing a member is a GitHub setting; rotating the client secret still ends
  every session at once; a member signing out revokes their token, and they can revoke zorgscope
  under "Authorized OAuth Apps".
* Bad: a stolen member cookie leaks a 7‑day session and an unscoped token that reads public data
  and identifies its owner — more than the expiry-only cookie of ADR‑0012 leaked. The cookie is
  confidential to anyone without the key, and the shorter member session bounds the window.
* Bad: a selection lives in one browser; a new device or an expired session means choosing again.
  Accepted for twelve checkboxes rather than reopening ADR‑0010.
* Bad: public repositories only. Private ones would need the `repo` scope, which grants write
  access to everything the member owns — too much for a triage page.
* Bad: the members repository is public, so the list of people who may use zorgscope is public.
* Neutral: twelve is the cap because the stylesheet has twelve plain hues; sectors are colours.
* Neutral: a member's sites form a family of their own that none of ADR‑0018's fixed radars
  names, so a member gets one radar with no switch; a member's fetch never carries ADR‑0017's
  per-owner tokens.
* Neutral: usage is visible in the log — sign-in, page view, fetch, sign-out with login and role —
  and nowhere else. A `/metrics` endpoint for Fly's Grafana is the follow-up if counting is wanted.

## Pros and cons of the options

### A second deployment

* Good: separate budget, branding and admission; the single-owner product stays exactly as is.
* Bad: a second Fly app, a second OAuth App, a second set of secrets, for a feature that is the
  same new subsystem either way.

### Organisation membership, a config allowlist, a CRUD page

* Good (membership): self-maintaining. Bad: `read:org` asks the member for more than identity.
* Good (config): no new mechanism. Bad: an edit and a deploy per person; the names in git.
* Good (CRUD page): the asked-for experience. Bad: a users table, which is a database, which
  ADR‑0010 removed for good reasons.

### The owner's token for everyone, or a pasted token

* Bad (owner's token): ten people refreshing twelve repositories each can exhaust the owner's
  five thousand requests an hour and make his own page stale.
* Bad (pasted token): the experience ADR‑0009 removed; the reason people would stop using it.

### A Fly Volume for the selection

* Good: a selection that follows a member across devices.
* Bad: a volume, migrations, a backup story and a machine pinned to one host, for twelve checkboxes.
```
